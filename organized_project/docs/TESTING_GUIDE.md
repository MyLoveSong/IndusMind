# 测试指南

本文档介绍如何测试 QWEN3-8B 产业报告生成系统的各项功能，确保整理后的项目结构没有破坏原有功能。

## 测试类型

### 1. 单元测试
- **位置**: `tests/` 目录
- **运行**: `python -m pytest tests/`
- **覆盖**: 各个模块的独立功能

### 2. 功能集成测试
- **脚本**: `scripts/test_functionality.sh`
- **运行**: `make test-func`
- **覆盖**: 端到端功能验证

### 3. 手动测试
- 启动完整系统后，通过浏览器验证前端功能

### 手动测试步骤

1. **启动系统**
   ```bash
   bash scripts/start_local_industry_report_stack.sh --with-frontend
   ```

2. **验证服务状态**
   ```bash
   bash scripts/check_services.sh
   ```

3. **测试前端功能**
   - 打开浏览器访问 http://127.0.0.1:5173
   - 点击"新建产业报告"
   - 填写报告信息并提交
   - 等待生成完成
   - 检查报告内容是否正确

4. **测试 API 接口**
   ```bash
   # 获取报告列表
   curl http://localhost:3000/api/reports

   # 创建报告
   curl -X POST http://localhost:3000/api/reports \
     -H "Content-Type: application/json" \
     -d '{"title":"测试报告","industry":"AI产业","scenario":"测试","objective":"验证功能","data_sources":[]}'

   # 生成报告
   curl -X POST http://localhost:3000/api/reports/{id}/generate \
     -H "Content-Type: application/json" \
     -d '{}'
   ```

## 常见问题排查

### 1. 服务启动失败
**问题**: 脚本执行后服务没有启动
**排查**:
- 检查日志文件: `logs/*.log`
- 确认端口是否被占用: `ss -ltnp | grep :3000`
- 检查依赖是否安装: `npm list` / `pip list`

### 2. API 调用失败
**问题**: curl 请求返回错误
**排查**:
- 确认后端服务正在运行: `curl http://localhost:3000/health`
- 检查请求格式和参数
- 查看后端日志: `tail -f logs/backend.log`

### 3. 前端无法访问
**问题**: 浏览器无法打开前端界面
**排查**:
- 确认前端服务启动: `curl http://localhost:5173`
- 检查防火墙设置
- 查看前端日志: `tail -f logs/frontend.log`

### 4. 报告生成失败
**问题**: 创建报告成功但生成失败
**排查**:
- 检查模型服务状态: `curl http://127.0.0.1:8001/health`
- 检查 RAG 服务状态: `curl http://127.0.0.1:8002/health`
- 查看后端生成日志

## 性能基准

### 报告生成时间
- **预期**: 30-120秒 (取决于报告复杂度)
- **超时**: 300秒

### 内存使用
- **模型服务**: ~4GB GPU 内存
- **RAG 服务**: ~2GB 系统内存
- **后端服务**: ~500MB 系统内存
- **前端服务**: ~300MB 系统内存

### 响应时间
- **API 健康检查**: <1秒
- **获取报告列表**: <2秒
- **创建报告**: <5秒
- **前端页面加载**: <3秒

## 持续集成

项目支持持续集成测试，可以在以下场景自动运行:

1. **代码提交**: 运行单元测试
2. **服务启动**: 运行功能测试
3. **定期检查**: 监控服务健康状态

## 故障排除

如果测试失败，请按以下顺序排查:

1. 检查系统资源 (CPU、内存、磁盘)
2. 检查网络连接和端口占用
3. 检查配置文件和环境变量
4. 查看详细日志文件
5. 重启相关服务
6. 检查依赖版本兼容性

如果问题持续存在，请查看项目文档或提交 Issue。
